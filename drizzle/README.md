# Drizzle migrations

Files in this directory are generated by `drizzle-kit generate`. **Do not edit them by hand** — edit `lib/db/schema.ts` and regenerate.

## How it works

1. `lib/db/schema.ts` is the source of truth for table structure.
2. Run `npm run db:generate` after changing the schema — Drizzle diffs against the previous state and writes a new `NNNN_*.sql` file here.
3. Run `npm run db:migrate` to apply pending migrations against `DATABASE_URL`. Drizzle tracks which have been applied in a `__drizzle_migrations` table it creates automatically.

## Baselining an existing database

The first migration (`0000_*.sql`) recreates every table from scratch. If your database already exists and was created by the legacy `scripts/migrate.ts`, applying `0000` will fail because the tables already exist.

To baseline (mark `0000` as already applied without running it):

```sql
-- Run once against the existing database:
CREATE SCHEMA IF NOT EXISTS drizzle;
CREATE TABLE IF NOT EXISTS drizzle.__drizzle_migrations (
  id SERIAL PRIMARY KEY,
  hash TEXT NOT NULL,
  created_at BIGINT
);

-- Get the hash for 0000 from drizzle/meta/_journal.json, then:
INSERT INTO drizzle.__drizzle_migrations (hash, created_at)
VALUES ('<hash-from-journal>', EXTRACT(EPOCH FROM NOW())::bigint * 1000);
```

After this, `npm run db:migrate` will skip `0000` and only apply newer migrations.

## Transition plan

- **Right now:** Both systems coexist. `npm run migrate` (legacy, additive SQL in `scripts/migrate.ts`) still works for the existing database. `npm run db:generate` is used for any new schema changes going forward.
- **Eventually:** Once baselined and verified, delete `scripts/migrate.ts` and rename `npm run db:migrate` to `npm run migrate`.

## Workflow for a schema change

```bash
# 1. Edit lib/db/schema.ts
# 2. Generate the migration SQL
npm run db:generate

# 3. Review the generated SQL in drizzle/NNNN_*.sql
# 4. Apply locally
npm run db:migrate

# 5. Commit both the schema change AND the generated SQL file
```

## Other commands

- `npm run db:push` — sync schema directly to the database without writing a migration file. Useful for prototyping; don't use in production.
- `npm run db:studio` — opens a browser GUI to browse data.
